Computer Architecture Case Study

RISC-V CPU Design in Logisim Evolution

I built a RISC-V processor datapath with reusable Logisim subcircuits, instruction decode, register state, memory access, branch/jump control, and trace-based verification against Venus reference output.

This project was completed as UC Berkeley CS61C coursework. To avoid turning the public internet into a course-solution archive, this page explains the architecture, verification approach, and engineering takeaways while the full implementation remains private.
RISC-V Instruction execution across arithmetic, branch, jump, memory, and immediate formats.
Logisim Datapath and control logic built from digital circuit subcomponents.
Verified Pipelined integration tests and custom assembly tests pass locally.

What I Built

The CPU is organized around a top-level processor circuit composed of smaller, testable subcircuits. I implemented the ALU, register file, control logic, immediate generation, branch comparison, partial loads, partial stores, and memory-facing datapath behavior needed to execute RISC-V programs.

The most interesting part of the project was debugging the CPU as a state machine: every incorrect control signal or datapath mux choice showed up as a divergence in register values, program counter updates, or memory-visible behavior.

Verification

Unit Tests

  • ALU operations
  • Register file reads/writes and hardwired zero register
  • Immediate generation for RISC-V formats
  • Branch comparison
  • Partial load and store behavior

Integration Tests

  • Register behavior across instruction execution
  • Branch and jump control flow
  • Memory loads and stores
  • Basic RISC-V programs including Fibonacci and power
  • Custom R/I/B/U-type assembly tests

Verified locally with commands such as bash test.sh part_b --pipelined and bash test.sh run_custom --pipelined, using Java headless mode for terminal-based Logisim simulation.

Why It Matters

This project demonstrates low-level systems thinking: understanding how software instructions become hardware state transitions, how control logic coordinates datapath components, and how to debug correctness through repeatable traces rather than guesswork.

The same engineering mindset transfers directly to production software and machine learning systems: understand the system, isolate failure modes, and build confidence with tests before calling something done.
